# OutlineFlow：最优解方向分析
**日期：** 2026-06-27  
**基准：** `outputs/ckpt.pt`（plan_id 分组，n_max=140，5000 steps，1.33M params）  
**当前指标：** FID 190.5 / Density 0.052 / Coverage 0.060（plan_id）；FID 129.2 / Density 0.044 / Coverage 0.035（unit_id）

---

## 核心瓶颈：单一全局向量条件

所有问题归结为同一条因果链：

```
轮廓 → OutlineEncoder (max-pool + mean-pool) → 单个 128-dim 全局向量
       ↓
每个 room token 看到的条件完全相同，无空间差异
       ↓
模型学不到"哪个 token 应该去哪个区域"
       ↓
房间数量方差崩塌：real 37±20，gen 31±6
       ↓
presence 阈值校准落到 -1.031（低于 padding 基线 -1）
       ↓
noise slot 被当成真实房间 → gap-fill 掩盖整个布局
       ↓
FID 3682 / Density ≈ 0 / Coverage ≈ 0
```

---

## 方向一：加 Cross-Attention（P0 — 结构性修复）

**预期提升：FID 大幅下降，Density 从 ≈0 → 有效值**

### 问题
`OutlineEncoder`（`model.py:32-47`）将 128 个边界点 max-pool/mean-pool 成单个向量，空间信息完全丢失。每个 room token 接收完全相同的条件 `c`，无法学习空间分配。

### 修复
在每个 `AdaLNZeroBlock` 的 self-attention 之后，新增一层 cross-attention，让 room token 作为 Q，128 个边界点作为 K/V：

```python
# AdaLNZeroBlock.__init__ 中新增
self.cross_attn = nn.MultiheadAttention(d_model, n_heads, batch_first=True)
self.ln_cross = nn.LayerNorm(d_model, elementwise_affine=False)
self.ada_cross = nn.Sequential(nn.SiLU(), nn.Linear(d_model, d_model))
nn.init.zeros_(self.ada_cross[-1].weight)
nn.init.zeros_(self.ada_cross[-1].bias)

# AdaLNZeroBlock.forward 中，self-attention 之后新增
a_cross, _ = self.cross_attn(self.ln_cross(h), boundary_pts, boundary_pts, need_weights=False)
h = h + self.ada_cross(c).unsqueeze(1) * a_cross
```

`OutlineEncoder` 改为同时输出全局向量（用于 AdaLN 时间注入）和点级特征序列 `[B, 128, d_model]`（用于 cross-attention K/V）：

```python
class OutlineEncoder(nn.Module):
    def forward(self, outline):          # [B,P,4]
        h = self.pt(outline)             # [B,P,d_model]
        pooled = self.proj(torch.cat([h.max(1).values, h.mean(1)], -1))  # [B,d]
        return pooled, h                 # 全局向量 + 点级特征
```

**改动范围：** 仅 `model.py`，约 30 行。

## 方向二：三个零成本修复（先做，验证 pipeline）

**预期提升：FID 小幅改善，训练更稳定，permutation-invariance 真正生效**

### 2a. 修复 slot 排列时机
**文件：** `train.py:85`（`build_tensors` 在训练前调用一次）

当前 `build_x1` 的随机 slot 排列在训练开始前固定，整个训练过程每个 plan 的 slot 分配不变，permutation-invariance 从未被利用。

```python
# 修复：在每个 batch 采样时重新排列
# train.py 训练循环内，idx 采样后：
x1_batch = reshuffle_slots(X[idx], rng)  # 每 step 重排
```

### 2b. 修复 padding slot 的 type 编码
**文件：** `params.py`，`build_x1` 函数

padding slot 的 type channel 当前为 0，与真实 slot 的 `{-1, +1}` 编码不一致，导致流路径中的 target 不一致。

```python
# 修复：padding slot type 全部填 -1
x[padding_slots, 7:] = -1.0   # 而非默认的 0
```

### 2c. 使用全量数据 + 更多 steps
**文件：** `train.py:46`，默认 `--msd_limit 2000`

当前只使用 5372 个 plan 中的 2000 个（37%），训练约 1600 个 plan，明显欠拟合。

```bash
python train.py --data_csv <path> --msd_limit 5372 --steps 20000
```

## 方向三：房间数量条件化（P1 — 解决数量方差崩塌）

**预期提升：Density 进一步提升，生成结果多样性增加**

### 问题
全局池化向量无法编码房间数量信息，导致生成数量方差远低于真实值（6 vs 20）。

### 修复选项 A：轮廓面积预测房间数
从轮廓面积/周长回归期望房间数，embed 后加到条件向量：

```python
# 在 OutlineFlow.forward 中
norm_area = outline_area / cfg.ref_area   # 归一化面积
count_emb = self.count_proj(norm_area.unsqueeze(-1))   # [B, d]
c = c + count_emb
```

### 修复选项 B（快速验证）：presence 阈值硬约束
在 eval 时禁止阈值低于 -0.8，避免 noise slot 被当成房间：

```python
# sample_eval.py / generate.py
presence_thresh = max(calibrated_thresh, -0.8)
```

## 方向四：Classifier-Free Guidance（P2 — 提升 Coverage）

**预期提升：Coverage 指标提升，生成结果更贴合轮廓**

训练时以概率 `p=0.1` 将轮廓条件替换为零向量，推理时使用 guidance scale：

```python
# train.py，fm_loss 调用前
if np.random.rand() < 0.1:
    outline_batch = torch.zeros_like(outline_batch)   # drop condition

# flow.py，sample 函数中
v_uncond = model(x, t, torch.zeros_like(outline))
v_cond   = model(x, t, outline)
v = v_uncond + guidance_scale * (v_cond - v_uncond)  # scale=1.5
```

**改动范围：** `train.py` + `flow.py`，约 15 行。
